# zabbix_action_trigger (Data Source)

Looks up an existing Zabbix trigger action by ID or exact name.

Give exactly one of `action_id` or `name`. Name lookup is exact and fails when
more than one visible action has the same name; use `action_id` to disambiguate.
An empty result can also mean that Zabbix permissions hide the action.

When migrating from the former Framework provider, replace its `id` lookup
argument with `action_id`. The resolved action ID remains available as the
standard data-source `.id`. SDK v2 represents nested singleton blocks as
one-element lists, so expressions such as `filter.evaluation_type` become
`filter[0].evaluation_type`.

## Example Usage

```terraform
data "zabbix_action_trigger" "example" {
  name = "Notify infrastructure failures"
}

output "action_id" {
  value = data.zabbix_action_trigger.example.id
}
```

### Optional

- `name` (String) Trigger action name. Exactly one of `action_id` or `name` must be given.

### Read-Only

- `escalation_period` (String) Default escalation period.
- `filter` (List of Object) Conditions that select trigger events. (see [below for nested schema](#nestedatt--filter))
- `id` (String) The ID of this resource.
- `notify_if_canceled` (Boolean) Whether to notify when an escalation is canceled.
- `operations` (List of Object) Problem escalation operations. (see [below for nested schema](#nestedatt--operations))
- `pause_suppressed` (Boolean) Pause escalation for suppressed problems.
- `pause_symptoms` (Boolean) Pause escalation for symptom problems. Zabbix 6.4 or newer is required to set this false; Zabbix 6.0 uses the default true state.
- `recovery_operations` (List of Object) Operations run when the problem recovers. (see [below for nested schema](#nestedatt--recovery_operations))
- `status` (String) Whether the action is enabled or disabled.
- `update_operations` (List of Object) Operations run when the problem is updated. (see [below for nested schema](#nestedatt--update_operations))
